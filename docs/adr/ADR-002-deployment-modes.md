# ADR-002. Два режима инсталляции: demo и corporate

**Статус:** принято
**Дата:** 2026-09-20

---

## Контекст

У продукта два сценария использования, и они предъявляют противоположные
требования к данным:

1. **Учебный и портфолийный.** Требование курса — приложение развёрнуто и
   доступно онлайн по публичному URL. Без этого проект не принимается.
2. **Рабочий.** Продукт предназначен для применения внутри компании, с реальными
   данными трекера — названиями задач, исполнителями, сроками релизов.

Реальные корпоративные данные не должны оказаться в публично доступном
приложении. Одновременно нельзя отказаться от публичного деплоя.

## Решение

Одна кодовая база, две инсталляции, разделённые флагом окружения `APP_MODE`.

| Аспект | `demo` | `corporate` |
|---|---|---|
| Доступность | публичный URL | закрытый контур |
| Источник данных | сид-генератор, синтетика | импорт из Yandex Tracker |
| База данных | Supabase Cloud | Postgres в периметре компании |
| Коннектор к трекеру | отключён на уровне сборки | включён |
| Сброс демо-данных | доступен всем | отсутствует |
| Регистрация | открытая | по инвайтам |

**Инвариант:** в режиме `demo` код физически не имеет доступа к коннектору
трекера — это проверяется тестом, а не дисциплиной разработчика.

## Данные, передаваемые в LLM

Движок риска считает метрики самостоятельно, поэтому модели для объяснения
нужны **числа, а не содержимое задач**. Это позволяет по умолчанию не
передавать наружу чувствительные тексты.

**Правило:** в LLM уходит `ReleaseMetrics` — агрегаты, коды причин, факты вида
`{ team: 'QA', load: 1.35 }`, идентификаторы и приоритеты задач. Названия задач,
имена исполнителей и комментарии **по умолчанию не передаются**.

Режим `corporate` получает настройку `LLM_PAYLOAD_LEVEL`:

| Уровень | Что уходит в модель |
|---|---|
| `metrics` (по умолчанию) | только агрегаты и коды причин |
| `titles` | дополнительно названия задач (включается осознанно) |
| `full` | названия и исполнители — требует явного согласования с ИБ |

Побочный эффект, полезный сам по себе: на уровне `metrics` промпт компактный,
запросы дешевле и быстрее, а prompt caching работает эффективнее.

## Последствия

**Плюсы:**
- требование курса о публичном деплое выполняется без риска утечки;
- продукт изначально пригоден к внедрению в закрытом контуре;
- ограничение на передачу данных в LLM заложено в архитектуру, а не добавляется
  под давлением службы безопасности постфактум.

**Минусы:**
- нужно поддерживать два конфигурационных профиля и проверять оба в CI;
- часть функций демонстрируется только на синтетике.

## Открытый вопрос

Для реального внедрения в корпоративном контуре потребуется решить, допустимо ли
обращение к внешнему LLM API вообще. Альтернатива — локальная модель для слоя
объяснений. Архитектура это допускает: слой объяснений изолирован и заменяем,
движок расчёта от модели не зависит. Решение вне рамок учебного проекта.
