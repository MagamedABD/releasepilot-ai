# Подключение внешних сервисов

Код для всех пунктов ниже написан и проверен. Каждому нужен ключ или
настройка в чужом сервисе — это делает владелец аккаунта, не код. Пока ключа
нет, функция выключена и говорит об этом на экране; остальное приложение
работает.

Переменные задаются в Vercel: **Project → Settings → Environment Variables**,
окружение Production. После изменения нужен новый деплой (**Deployments → ⋯ →
Redeploy**): значения `NEXT_PUBLIC_*` подставляются при сборке.

## 1. Почта: дайджест и оповещение о росте риска (FR-43, FR-44)

Что делает: каждый день вместе со снимком метрик сравнивает уровень риска с
прошлым снимком и пишет менеджерам, если он вырос; по понедельникам шлёт
статус всех открытых релизов. Кнопка «Отправить себе на почту» в статусе
для руководства — то же письмо по одному релизу.

1. Зарегистрироваться на [resend.com](https://resend.com).
2. **Domains → Add Domain**, добавить свой домен и внести DNS-записи, которые
   покажет Resend. Без подтверждённого домена письма уходят только на адрес
   владельца аккаунта.
3. **API Keys → Create API Key**, право *Sending access*.
4. В Vercel задать:
   - `RESEND_API_KEY` — ключ из шага 3;
   - `DIGEST_FROM_EMAIL` — отправитель на подтверждённом домене, например
     `ReleasePilot <status@ваш-домен.ru>`.

Проверка: открыть ассистента любого релиза → «Статус для руководства» →
«Отправить себе на почту». Письмо придёт на адрес учётной записи.

Получатели рассылки — владелец, администраторы и менеджеры организации.
Демо-персонажи с адресами `@example.com` пропускаются. Оповещение о росте
риска видно и без почты: плашка в кокпите и отметка «↑ вырос со вчера» в
списке релизов.

## 2. Вход через Google и GitHub (FR-01)

Адрес возврата для обоих провайдеров один:
`https://<project-ref>.supabase.co/auth/v1/callback` — он показан в Supabase
на странице провайдера.

**GitHub**

1. GitHub → **Settings → Developer settings → OAuth Apps → New OAuth App**.
   *Homepage URL* — адрес сайта, *Authorization callback URL* — адрес
   возврата выше.
2. Скопировать *Client ID*, сгенерировать *Client secret*.
3. Supabase → **Authentication → Providers → GitHub**: включить, вставить оба
   значения.

**Google**

1. [console.cloud.google.com](https://console.cloud.google.com) → создать
   проект → **APIs & Services → OAuth consent screen** (тип External).
2. **Credentials → Create Credentials → OAuth client ID**, тип *Web
   application*; в *Authorized redirect URIs* — адрес возврата выше.
3. Supabase → **Authentication → Providers → Google**: включить, вставить
   *Client ID* и *Client secret*.

**Включить кнопки**

В Vercel задать `NEXT_PUBLIC_OAUTH_PROVIDERS` — `google,github` или один из
них — и передеплоить. Кнопка появляется только для перечисленных: включённый
в Supabase провайдер без этой переменной не показывается, а кнопка без
включённого провайдера вела бы на страницу ошибки.

Адрес сайта должен быть в Supabase → **Authentication → URL Configuration →
Redirect URLs** (для Vercel он там уже есть — см. README, раздел «Деплой»).

## 3. Ассистент на сайте (FR-24) — подключён 2026-10-17

Локально ассистент работает на модели через Ollama (README, «Ассистент на
локальной модели»). На Vercel до `localhost` не достать — нужен ключ Claude
API: `ANTHROPIC_API_KEY` в переменных Vercel (тип Secret). Подписка Claude Max
включает ежемесячные кредиты API: в Claude Console → Billing их нужно
привязать кнопкой «Link and claim», после чего создать ключ в API Keys
(scope — Default workspace). У ключа есть срок действия; после него
ассистент снова отвечает «не настроен», пока не задан новый. Без него ассистент отвечает
«недоступен», а статус для руководства, кокпит и сценарии работают.

## 4. Импорт из Yandex Tracker (FR-40)

Только в отдельной корпоративной инсталляции (ADR-002): `APP_MODE=corporate`,
`TRACKER_OAUTH_TOKEN`, `TRACKER_ORG_ID`. В публичное демо эти переменные не
добавляются. Форма — «Настройки → Импорт → Из Yandex Tracker»; в демо-режиме
на её месте объяснение, почему она недоступна.
